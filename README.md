# Web Application Skeleton

## Quick Start

```bash
composer install
cp .env.dist .env
php bin/console orm:schema-tool:create
composer serve
```

Open http://localhost:8080

## Architectural Overview

This skeleton employs a hybrid architectural approach, leveraging the strengths of MVC, ADR, and MVVM:

*   **MVC (Model-View-Controller):** Guides the overall separation of concerns, ensuring a clear division between data, presentation, and logic.
*   **ADR (Action-Domain-Responder):** Provides a clear, streamlined request handling flow. Incoming requests are handled by `Actions`, which orchestrate business logic via the `Domain` layer and prepare data for presentation using `Responders`.
*   **MVVM (Model-View-ViewModel):** Enhances the UI layer. `ViewModels` bridge the data prepared by `Responders` and the `View` templates, handling UI-specific state and presentation logic.

The `index.php` file serves as the single entry point (front controller) and application bootstrap, managing the HTTP request and response lifecycle. Dependency Injection is utilized for managing component wiring throughout the application.

```
│   │   ├── Model/           # Data models and entities
│   │   ├── Repository/      # Data repositories
│   │   └── Service/        # Domain services containing business rules
│   ├── Responder/           # ADR: Response generators (JSON, HTML, etc.)
│   ├── View/                # Presentation templates (Twig, Blade, etc.)
│   ├── ViewModel/           # MVVM: Prepares data for views
│   └── Event/               # Event listeners
├── var/

│       └── database.sqlite
├── tests/                    # Automated tests
├── composer.json
├── composer.lock

```

## Key Components and Responsibilities

*   **`index.php` (Kernel Launcher):**
    *   Loads Composer's autoloader.
    *   Initializes the Dependency Injection (DI) container.
    *   Loads application configuration (routes, DI definitions, etc.).
    *   Sets up global error and exception handling.
    *   Manages the HTTP request and response lifecycle.
    *   Dispatches the request to the router.
    *   Executes the appropriate `Action` based on the route.
    *   Returns the final HTTP response generated by the `Responder`.
*   **Routing:** Maps incoming URLs and HTTP methods to specific `Action` classes, parsing parameters.
*   **ADR - Action:** Receives request data, performs input validation, invokes `Domain` services for business logic, and passes results to the `Responder`.
*   **ADR - Domain (Models, Services):** Encapsulates core business logic, interacts with the ORM for data persistence, and defines DTOs.
*   **ADR - Responder:** Receives processed data from the `Action`, formats it for output (JSON, HTML), interacts with `ViewModel`s and `View` templates, and generates the final HTTP response.
*   **MVVM - ViewModel:** Prepares data specifically for a `View`, managing UI-specific state and presentation logic, abstracting complexity from the `View`.
*   **View:** The presentation layer (e.g., using Twig, Blade) that renders HTML, primarily receiving data from a `ViewModel`.
*   **Dependency Injection Container:** Manages the instantiation and wiring of all application components, configured in `config/di.php`.

## Getting Started

### 1. Project Setup & Dependencies

```bash
composer create-project prototype-in/web-skeleton-app my-new-project --repository='{"type": "vcs", "url": "https://gitlab.com/prototype.in/web-skeleton-app.git"}' --stability=dev
cd my-new-project
composer install
```

### 2. Environment Setup

```bash
cp .env.dist .env
```

See `.env.dist` for available configuration options.

### 3. Database Setup (Doctrine ORM + SQLite)

This project uses Doctrine ORM 4.x with SQLite for data persistence.

#### Quick Start

1. **Create database schema:**
   ```bash
   php bin/console orm:schema-tool:create
   ```

2. **Run migrations (optional, for additional schema):**
   ```bash
   # Run SQL migrations from migrations/ directory
   sqlite3 var/data/database.sqlite < migrations/001_roles_sti.sql
   ```

3. **Update schema (after entity changes):**
   ```bash
   php bin/console orm:schema-tool:update --force
   ```

#### Available Commands

| Command | Description |
|---------|-------------|
| `php bin/console orm:schema-tool:create` | Create schema from entities |
| `php bin/console orm:schema-tool:update` | Update schema (safe for dev) |
| `php bin/console orm:schema-tool:drop --force` | Drop all tables |
| `php bin/console orm:info` | Show entity mapping info |
| `php bin/console orm:validate-schema` | Validate ORM schema |

#### Database Location

- SQLite database: `var/data/database.sqlite`

### 3. Running the Application

```bash
php -S localhost:8080 -t public/
```

Then, open your web browser and navigate to `http://localhost:8080`.

### 4. Example: Register User

```bash
curl -X POST http://localhost:8080/register \
  -H "Content-Type: application/json" \
  -d '{"email":"test@example.com","password":"password123","firstName":"John","lastName":"Doe"}'
```

The application uses Monolog for logging. Logs are written to `logs/app.log` (gitignored).

To view logs in real-time:

```bash
tail -f logs/app.log
```
